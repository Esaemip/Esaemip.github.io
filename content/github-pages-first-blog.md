## 왜 GitHub Pages였나 {#why-pages}

처음 받은 미션은 학습 과정과 활동을 꾸준히 정리할 개인 블로그를 만드는 것이었다. 개발, CTF, 버그바운티처럼 앞으로 쌓을 기록이 많아서 단순한 소개 페이지보다는 글을 계속 추가할 수 있는 공간이 필요했다.

GitHub Pages는 저장소에 올린 HTML과 CSS를 그대로 웹사이트로 보여준다. 파일을 수정하고 Git으로 올리는 과정 자체가 공부가 된다는 점도 첫 블로그에 잘 맞았다.

## 저장소와 첫 화면 {#first-screen}

`Esaemip.github.io` 저장소를 만들고 컴퓨터로 복제한 다음, 가장 먼저 `index.html`과 `journal.css`을 준비했다. 이후 카테고리 페이지와 글 파일을 따로 나눠, 기록이 늘어나도 첫 화면이 복잡해지지 않게 정리했다.

> [!NOTE] 처음 알게 된 점
> 내 컴퓨터에서 연 파일은 나에게만 보이지만, 같은 파일을 GitHub에 올리고 Pages로 배포하면 누구나 주소로 들어올 수 있다.

## 마음에 들 때까지 고친 디자인 {#design}

처음부터 지금 모습이었던 건 아니다. 실사 여우도 넣어 보고, 마인크래프트 느낌도 시도해 봤지만 내가 원한 분위기와는 달랐다. 결국 조금 댕청해 보이는 흰 여우, 차분한 종이색 배경, 계속 내리는 눈을 중심으로 다시 정리했다.

문구도 마찬가지였다. 멋있어 보이는 말보다 실제로 내가 말할 법한 문장을 남기는 편이 훨씬 자연스러웠다. 여러 번 빼고 고치는 동안 디자인은 무언가를 더하는 일만큼 덜어내는 일도 중요하다는 걸 배웠다.

## GitHub에 올리고 배포하기 {#publish}

수정한 파일은 아래 순서로 저장소에 올렸다. `add`는 올릴 파일을 고르고, `commit`은 그 변경에 이름을 붙여 저장하며, `push`는 GitHub로 보내는 명령이다.

```powershell
git add .
git commit -m "새 기록 작성"
git push origin main
```

그다음 저장소의 **Settings → Pages**에서 `main` 브랜치와 `/(root)`를 선택했다. 배포에는 바로 반영되지 않고 잠깐 시간이 걸릴 수 있었고, 예전 화면이 남으면 `Ctrl + F5`로 새로 불러왔다.

## 이제부터 채울 것들 {#next}

홈 화면만 있는 상태에서 끝내지 않기 위해 여섯 카테고리를 각각 들어갈 수 있게 연결했다. 지금 읽는 이 글이 그중 첫 번째 게시글이다.

- 개발하다 막힌 원인과 해결 과정
- CTF 문제를 풀 때 했던 생각과 실패한 접근
- 읽은 기술문서와 논문에서 생긴 질문
- 공모전과 자격증을 준비하며 바꾼 공부 방법

처음부터 완벽하게 쓰기보다, 실제로 부딪힌 일을 한 편씩 남겨보려고 한다. 나중에 다시 봤을 때 그때의 내가 어디서 막혔고 어떻게 넘어갔는지 알 수 있다면 충분하다.
